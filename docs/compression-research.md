# Compression research — making worlds weigh less (research tick, 2026-11)

Question: what old and new innovations — codec families, mathematical
transforms, semantic tricks — can push the BLOCK side of the container below
the current x6.42-vs-Anvil / compact x0.11 state? Sources: web landscape
(community + academic) and an offline codec probe on the real corpus
(24,809,708 bytes of decompressed Anvil chunk payload from
`bench-corpus/dim/region`, compressed in 4 MiB independent blocks = the
slab-equivalent window). Probe script: `scripts/codec_probe.py` (sandbox).

## 1. The offline codec probe (real corpus, hard numbers)

| codec | size | vs raw | wall (1T) | vs zstd-6 |
|---|---|---|---|---|
| zstd -6 (current cold default) | 1,575,078 | 0.0635 | 0.18 s | — |
| zstd -12 | 1,512,559 | 0.0610 | 0.36 s | -4.0% |
| zstd -19 (zstd family ceiling) | 1,296,994 | 0.0523 | 4.67 s | -17.7% |
| **xz / LZMA2 -6 (4 MiB dict)** | **1,185,140** | **0.0478** | 3.79 s | **-24.8%** |
| lzma2 -3 | 1,368,256 | 0.0552 | 0.72 s | -13.1% |
| **brotli -11** | **1,155,216** | **0.0466** | 29.7 s | **-26.7%** |
| brotli -9 | 1,475,838 | 0.0595 | 0.63 s | -6.3% |
| bzip2 -9 (BWT reference) | 1,508,594 | 0.0608 | 2.42 s | -4.2% |
| lzma2 -6 + delta(4B) | 1,694,702 | 0.0683 | 3.81 s | **+7.6% NEGATIVE** |
| lzma2 -6 lc=0/1/2 lp=0 | ~1,168-1,172k | 0.0471-2 | 4.3 s | flat — defaults optimal |
| transpose8 + lzma2 -6 | 1,664,413 | 0.0671 | 4.76 s | **+43% NEGATIVE** |

Window-size lever, probed separately (whole 24.8 MB single window vs 4 MiB
blocks): zstd-6 -0.5%, zstd-19 -2.2%, zstd-22+LDM w27 -1.0%, lzma2 -6 -1.7%.
**The window lever is dead on this corpus** — content-addressed dedup already
removed the cross-slab redundancy a bigger window would catch (consistent
with the entropy-floor map: zstd exploits cross-section matches). Growing
`slab_max_raw` buys ~1-2% at real random-read cost. Not recommended.

**Headline verdict: LZMA2 -6 beats the ENTIRE zstd family** (the current
cold codec) by -24.8%, and even beats zstd-19 by -8.6% while compressing in
the same wall time (3.8 s vs 4.7 s). brotli -11 is 2.5% smaller than LZMA2-6
but 8x slower — an archival-only setting. Delta pre-transforms, byte-plane
transposes and LZMA literal-context tuning are all documented NEGATIVE on
NBT/voxel material. BWT (bzip2 here; bzip3 by the same evidence, it targets
text/code) does not bite voxel NBT.

Integration shape (next dev tick): a cold-tier codec enum (`bulk_compress`
vs lzma2 via `lzma-rs`/`xz2`), `CSAVES_COLD_CODEC=lzma2` opt-in first. Pack
wall on this corpus: 3.8 s single-thread ≈ 1.9 s on the 2-core sandbox /
≈ 1 s on 4-core CI — 2-5x the current 0.41 s pack at z6, which the pack
watermark absorbs in the background; the CI ratio gates (survival x3.0,
jj x2.6 floors) would clear with ~-25% margin. Default stays z6 until the
pack-wall TPS telemetry is re-checked.

## 2. The semantic lever: pristine-chunk elision (the 10-50x class)

Codec work fights the entropy floor byte by byte (-25% at best). The lever
that skips bytes ENTIRELY: chunks whose content the server can reproduce
deterministically from the seed do not need storing at all.

Regenerating chunks from the seed is established, safe Minecraft practice:
the Bedrock Editor's chunk management resets terrain "to its original
seed-generated state", community tutorials update old worlds by DELETING
chunks so they regenerate under the new version, and PaperMC threads use the
same mechanism for explored-but-unused terrain. Vanilla semantics: a missing
chunk is regenerated by the current generator — version-drift-immune by
construction.

Design sketch for c-saves:

- Paper side: freshly generated chunks (first save, never player-modified —
  the server knows the difference between a generation write and a load
  write) get a `pristine` marker on the import call.
- Rust side: a new recipe kind with ZERO blobs — just the payload hash.
  The existing unchanged-write fast path (hash match -> O(1)) already
  absorbs Paper's autosave re-serializations of such chunks: pristine stays
  pristine until the content hash actually changes.
- Read path: a pristine recipe resolves to "not stored" -> the server
  regenerates (identical semantics to a deleted region file).
- Integrity: elide ONLY on exact payload match; any mutation flips the
  chunk to normal storage. The verify contract ("ok=N bad=0") extends with
  a pristine=N bucket.
- Impact on the JJ-class corpora (generated, never modified): the block
  bulk is structurally unique per chunk (ore noise breaks section dedup —
  the 12,130 members ARE that residue), so elision collapses the container
  to entities + tails + modified chunks — an order of magnitude, not a
  percent.
- Cost of admission: the CI ratio gates must be redefined (the JJ corpus
  would compress to near zero, making x-ratios meaningless) — gates move to
  the MODIFIED-content subset. This is a product decision, flagged as such.

## 3. Frontier (parked, with reasons)

- **Context-mixing / PAQ-ZPAQ class**: ZPAQ ultra measured 19.0% vs 7Z
  LZMA2 23.5% on a general 303 MB corpus (peazip maximum-compression
  benchmark) — expect -15-25% under LZMA2-6 here. Too slow for the pack
  pass (seconds per MiB); fits an OFFLINE "archive export" command
  (`csaves export --archive`): re-drain everything through the strongest
  available coder for cold storage, re-import on restore.
- **LLM + arithmetic coding** (ts_zip, LLMZip): ts_zip reaches 1.106 bpb on
  enwik8 vs xz 1.989 bpb — ~44% under LZMA-class on TEXT. Requires a
  deterministic predictor on both ends, GPU/CPU-seconds per MiB, and no
  evidence of gains on binary voxel NBT (models are not trained on it).
  Parked; revisit if per-world trained context models become practical.
- **Learned 3D-context arithmetic coding** (lossless point-cloud
  literature: octree+voxel hybrid coders, IEEE 2021 / arXiv 2025): the
  academically right way to beat LZ on voxel indices. Real implementation
  cost (a per-world model, deterministic decode); parked behind the same
  archival framing as ZPAQ.
- **bzip3**: BWT+context-mixing successor, strong on text/code
  (17 MiB/s/thread); BWT class already measured non-viable on voxel NBT
  via bzip2 above.

## 4. Recommended sequence

1. **LZMA2-6 cold tier, opt-in** (`CSAVES_COLD_CODEC`) — measured -24.8% on
   the real corpus, bounded pack-wall cost, zero semantic change, enc_fp
   pin untouched (member raws unchanged; only the slab compression changes).
2. **Pristine-chunk elision** — the order-of-magnitude lever for huge
   (generated, unmodified) worlds; needs the Paper-side marker + gates
   redesign decision.
3. **Archive export mode** (brotli-11 measured / ZPAQ-class expected) —
   offline, additive, no hot-path risk.
4. Documented negatives stand as gates against re-testing: delta filter,
   byte transpose, lc/lp tuning, BWT family, window growth.

Probe sources: peazip brotli-vs-zstd and maximum-compression benchmarks,
bellard.org/ts_zip, LLMZip (arXiv/OpenReview), bzip3 project pages,
Minecraft Bedrock Editor chunk management docs, community terrain-update
tutorials, PaperMC forums on chunk regeneration, LinearRegionFileFormat
(Modrinth) as format-level prior art.

## 5. Integration verdict (v0.9.41): LZMA2 shipped as opt-in

Recommendation 1 landed the same tick-series. Real-container numbers
(bench_size, 9216 chunks, 5 edit rounds; CSAVES_COLD_CODEC=lzma2):

| metric | zstd-6 (default) | LZMA2 preset 6 | delta |
|---|---|---|---|
| compact container | 3.80 MiB | **3.02 MiB** | **-20.5%** (x0.08 vs anvil) |
| slab bulk (records_frame comp) | 3,723,428 B | 2,907,791 B | -21.9% |
| fresh/hot container | 10.97 MiB | 10.97 MiB | unchanged (raw hot tier) |
| import ST | 126 MB/s | 126 MB/s | unchanged |
| verify | 728+218 bad=0 | 728+218 bad=0 | equal |

The offline probe's -24.8% lands as -20.5% on the whole container: recipes,
per-blob cold re-stores and dict files stay zstd by design (their dict_id
slots carry real dict ids; slabs carry the bulk). The wire carries the
codec in the slab record's dict_id byte as the 0xFE sentinel (dict-version
space capped at 253), so the single decompress() hook dispatches every read
path. Pack wall is the documented opt-in trade (~2-5x, comp-bound,
per-stream parallel).

Remaining roadmap items from this research: archive export mode (brotli -11
measured / ZPAQ-class expected), and the frontier items stay parked.

## 6. Per-section entropy coding: measured NEGATIVE end-to-end (research tick 2)

The natural next question after LZMA2: the canonical voxel streams carry
order-0..2 redundancy that fixed-width bit-packing wastes — entropy coding
(rANS / arithmetic with adaptive counts) should harvest it. Probed with
exact mathematics on the real corpus (1,198 sections, 4.9M voxels,
`scripts/entropy_probe.py` + `kt_adaptive_probe.py`, sandbox):

**Probe 1 — per-section static rANS (order-0, quantized freqs):** raw
section bodies drop -55.7% (1,280,355 -> 567,519 B). End-to-end the verdict
FLIPS: zstd-6 on the CURRENT dense/RLE assembly reaches 355,694 B — the
rANS output (near-random bits) compresses to nothing further and lands at
554,429 B (+56% WORSE). LZMA2-6 on the dense assembly: 284,208 B — already
2x BELOW the per-section order-0 entropy floor (550,467 B).

**Probe 2 — adaptive KT context modeling (context = left + above voxel,
K = 1<<W symbols, per-section cold start, no transmitted tables):** exact
sequential code length via the lgamma closed form
`L_c = log2(Γ(K/2+m)/Γ(K/2)) - Σ log2(Γ(k+1/2)/Γ(1/2))`:

| W | sections | KT-CM b/vox | LZMA2-on-dense b/vox | delta |
|---|---|---|---|---|
| 1 | 119 | 0.0499 | 0.0624 | -20% |
| 2 | 436 | 0.2228 | 0.2684 | -17% |
| 3 | 375 | 0.4076 | 0.4725 | -13.7% |
| 4 | 203 | 0.5853 | 0.6517 | -10.2% |
| 5 | 40 | 0.7612 | 0.7158 | +6.3% (dense keeps) |
| 6 | 25 | 1.4510 | 1.2735 | +13.9% (dense keeps) |

A -11.9% per-section win under LZMA2 — on paper. A full Rust implementation
(LZMA-convention carry range coder, KT-adaptive counts, wire form 3 in the
CSEC frame, decode in all three read paths, glob-conversion support,
shift-admission recalibration) was built, tested green (64/64), and parked
on branch `wip-cm-section-form` after the REAL-container A/B:

| corpus / codec | base 0.9.41 | + CM form 3 | verdict |
|---|---|---|---|
| JJ bench 64x4, z6 | 1.70 MiB (x0.11) | 1.85 MiB (x0.12) | **+8.8% WORSE** |
| JJ bench 64x4, LZMA2 | 1.35 MiB (x0.08) | 1.44 MiB (x0.09) | **+6.7% WORSE** |
| survival 16x12, z6 | x3.12 smaller | x2.80 smaller | **-10%, breaks the 3.0x gate** |

enc_fp raw member bytes DID drop -31.8% (9,971,843 -> 6,798,802; members
12130 unchanged — structural hashes are content-based; would-be pin
44b0fbd900bbc67a). **The raw win evaporates post-codec.**

Root cause, now measured three independent ways: the container's dominant
forms (GLOB gid streams, RLE, dense zero-run streams, shift-refs) win
through CROSS-SECTION byte alignment that the slab codec harvests at a
level BELOW any per-section entropy floor. zstd-6's match machinery on
aligned 1-byte-per-voxel gid streams beats a per-section coder the same
way LZMA2-on-dense did in probe 1. The offline probe's premise — that the
alternative to CM was the dense assembly — was wrong for the shipped
pipeline; the math was right, the baseline was not the real one.

**Anti-retest gates (do not revisit without new evidence):**
- per-section rANS/tANS/FSE on canonical voxel streams (order-0): dead.
- per-section adaptive CM (order-1/2, left+above contexts, KT or MAP):
  dead on both real corpora under both cold codecs.
- W >= 5 sections: CM loses even on paper (context starvation: 4096
  samples over up to 4096 contexts).
- byte-plane transposes, delta filters, BWT family, window growth: dead
  (section 1).

**What could actually beat glob+LZMA2 (frontier, parked):** a SLAB-LEVEL
global context model over the gid streams — order-1+ voxel-space contexts
maintained across the whole slab (the coder both encoder and decoder walk
the slab's sections in stored order, so the model needs no tables) — i.e.
replace the general-purpose slab codec with a domain coder. Multi-day
project, real read-latency cost on the cold path, expected gain bounded by
the gap between LZMA2-on-glob and the true joint entropy of the aligned
material (unmeasured; the per-section floors are NOT the bound). Revisit
only with a corpus where alignment-poor player-built content dominates.

## 7. Research tick 3 — the codec front closes: EXTREME ships, PPMd and the export framing die

Three questions were open after 0.9.42: (a) does the LZMA2 encode have any
left on its own knob, (b) does a GLOBAL context model over the slab material
(the frontier parked in §6) have a cheap proxy verdict, (c) what is an
archive-export mode actually worth now that the live cold tier is LZMA2.
All three got real measurements on the same corpora.

### 7.1 The preset ladder on the REAL member stream (shipped as 0.9.43)

`examples/lzma_preset_probe.rs` collects the canonical members of
`bench-corpus/dim` in first-occurrence (pack-like) order — 12,130 unique
members, 6.29 MiB stream raw with 24 B entry rows, one 8 MiB slab group —
and compresses that exact stream with liblzma presets:

| preset | bytes | vs p6 | wall |
|---|---|---|---|
| 6 (shipped through 0.9.42) | 940,873 | — | 2.5 s |
| 9 (dict 64 MiB) | 940,910 | +0.00% | 3.6 s |
| 6 + dict 64 MiB (isolate the window) | 940,910 | +0.00% | 3.7 s |
| **6 \| EXTREME** | **915,488** | **-2.70%** | 4.2 s |
| 8e / 9e (dict 64 MiB) / 9e + dict 8 MiB | 915,488 | -2.70% | 4.2 s |
| 1 (sanity floor) | 1,127,521 | +19.84% | 0.4 s |

Reading: the preset-6 dict (8 MiB) already covers the 8 MiB slab cap, so
the WINDOW lever is empty (+0.00% everywhere); every EXTREME variant lands
on identical bytes — the entire win is the deeper match search
(nice_len 273 vs 64). And because EXTREME touches only encoder search
parameters, the decode side stays `new_preset(6)`: same 8 MiB window, same
per-decode memory, byte-compatible both directions with every 0xFE stream.
**0.9.43 = the one-line encoder flag.** End-to-end on the bench corpus
(4096 chunks, 4 rounds): region slab bulk 1,306,138 -> 1,190,263 B
(-8.87%), compact container 1.35 -> 1.24 MiB, JJ x3.36 -> x3.71, survival
x4.01 -> x4.28, verifies 1661+946+1280 bad=0, enc_fp EXACT. The
synthetic-heavy bench material gains more than the noise-heavy JJ members
(-2.70%) — repetitive terrain feeds the deeper search superlinearly; the
pack C-step wall went 8.1 -> 22.5 s on the 2-core sandbox (background,
watermark-throttled, same accepted trade class as 0.9.41/42).

### 7.2 PPMd solid-window: the global-CM proxy measured NEGATIVE

The §6 frontier — "a slab-level global context model over the gid streams"
— has a cheap zero-implementation proxy: PPMd (order-N context model with
transmitted counts) over the whole material as ONE solid stream. Solid
framing also happens to be what an archive export would do. On the
24,809,708 B decompressed Anvil corpus (exact re-extraction, 728 chunks):

| coder (solid 24.8 MB) | bytes | vs lzma2-6 solid |
|---|---|---|
| lzma2-6 (4 MiB dict) | 1,175,626 | — |
| lzma2-9e (64 MiB dict) | 1,173,953 | -0.1% |
| **brotli -11** | **1,137,742** | **-3.2%** |
| ppmd-I order 16, 192 MiB | 1,247,326 | +6.1% |
| ppmd-H order 12/16 | 1,280,450 / 1,250,247 | +8.9 / +6.3% |
| bzip2 -9 | 1,507,514 | +28.2% |

Even at order-16 PPMd LOSES to LZMA2 by +6%: the material is
LZ-match-dominated (byte-aligned repeated structures, NBT headers, palette
runs), and LZMA2's literal coder already harvests the order-0/1 context.
A general-purpose CM cannot see the matches. The slab-CM frontier now has
TWO independent negatives (per-section CM §6, global CM here); what could
still beat LZ is a joint LZ+domain-CM mixer (PAQ class) — archival-only,
still parked, and its prior is now weaker.

### 7.3 The export lever downgraded to ~3%; the zstd residue is speed-pinned

- Archive export (re-drain everything solid through the strongest coder):
  best measured candidate brotli -11 = -3.2% vs the LZMA2 the live
  container already uses; solid-vs-grouped framing adds ~1%. NOT a feature
  on size alone. (ZPAQ's "-15-25% under LZMA2" prior from general-corpus
  benchmarks is contradicted for this material class by §7.2.)
- Recipe batches (kind-9, z6): deliberately z6 IN THE WRITE THREAD's
  critical path — z19 there measured ~49% of fresh-import wall in sync
  pauses; LZMA2 preset-6 on 192 KiB batches is ~50-100 ms each, worse.
  The pack pass re-points slabs, not batches, so there is no background
  moment to re-tier them. Architecture-pinned.
- Regular cold blobs (>64 KiB members, z6) and dict files: negligible
  absolute bytes at every measured scale (<2% of container, mostly <0.5%).
- The 8 MiB slab group cap already realizes the big-window lever (the
  profile_size S3 "bigger groups" rows are fossils of the 192 KiB era).

**Verdict: the codec era is measured-closed on every stream that matters.**
The remaining honest lever for "world weighs less" is SEMANTIC:
pristine-chunk elision (§2) — order-of-magnitude on generated worlds,
needs the Paper-side generation-write marker + ratio-gate redesign
decision. Probe artifacts: `scripts/solid_probe.py` +
`scripts/corpus_extract.py` (sandbox; corpus checksum 24,809,708 B
matches §1 bit-exact), `native/examples/lzma_preset_probe.rs` (in-repo).

## 8. Research tick 4 — pristine elision ships (v0.9.44): the codec era hands off to the semantic era

The §2 design landed as an OPT-IN feature (`CSAVES_PRISTINE=1`, region
stores only). Contract semantics (recipe mode 7, 17 B, zero blobs):

- first-ever write of a key -> contract (payload hash only);
- read -> None -> shim vanilla fallback -> NO_DATA -> Paper regenerates
  from the seed (identical to a missing chunk in a save format);
- different-content write -> normal pipeline supersedes the contract
  (flip-on-mismatch); identical re-save -> pristine fast path, stays a
  contract across restarts (the hash lives in the recipe, not RAM);
- import/strip/whole-mode paths exempt; verify gains a pristine=N bucket;
  two new tests (contract roundtrip/flip/reopen + default-off/import-exempt).

Real-container demo (bench 64x4, CSAVES_PRISTINE=1): fresh 5.08 -> 0.11 MiB
(x0.01 vs anvil), compact 1.24 -> 0.59 MiB (x0.04 vs anvil), compaction
22.8 -> 9.5 s. Flag OFF = byte-identical 0.9.43 behavior on every gate.

Residual risk (documented, operator-accepted): mutations between chunk
generation and the first-ever durable save ride inside the contract hash
and revert on regeneration — the same semantics as the Bedrock Editor
chunk-reset flows. The shim-side tightening (isNewChunk marker /
InhabitedTime==0 passed as a per-write flag) is future work; the Rust
contract already accepts it.

With this, the "make worlds weigh less" roadmap from §4 is fully resolved:
LZMA2 family (§5/§7.1) shipped; per-section entropy coding (§6) and global
CM (§7.2) measured dead; archive export (§7.3) measured not-worth-it; the
order-of-magnitude lever (§2) shipped opt-in. The codec front is closed;
the remaining frontier is the domain joint LZ+CM mixer (archival-only,
parked) and whatever new evidence arrives.

## 9. Research tick 5 — pristine import contracts (v0.9.45): the huge-world lever measured

§8 shipped live-path elision and left one deliberate exemption: imports.
Huge worlds ARE imports (the background Anvil drain of pregenerated
worlds), so the -90% class was unreachable exactly there — bigworld-survival
stood at x2.21 with no codec lever left (§7/§4). v0.9.45 turns the
exemption into an explicit operator mode: `CSAVES_PRISTINE=import|2` (or
`CSAVES_PRISTINE_IMPORT=1`): the import/strip write path may form recipe
mode 7 regeneration contracts like the live path already could.

Measured:

| corpus | pristine-off (0.9.44) | import-contracts (0.9.45) |
|---|---|---|
| real JJThunder region import, 728 chunks, anvil 4.47 MiB | 1.17 MiB compact, x0.26, import 0.2 s | **0.01 MiB, x0.002 (-99.8%), pristine=728 stored=0, import 0.0 s** |
| pure-pregen 9,216-chunk world (live path, 0 edits) | — (flag-off 1.24 MiB at 4096+edits) | **0.28 MiB, x0.01 vs anvil (-99.2%)**, 26 B/chunk, zero blobs |

The 26 B/chunk is the contract's honest all-in cost (17 B mode-7 body +
record/batch overhead, measured over 9,216 recipes). Arithmetic projection
(labeled as such): bigworld-survival's 261,572 region chunks ≈ 6.8 MB of
contracts against 2,136 MiB of Anvil — the -90% target clears by two
orders of magnitude for pure-worldgen ingests.

Safety model (unchanged mechanics, new operator surface): imported content
is ASSERTED seed-reproducible; on restore, any re-save that hashes
differently (fresh light after relight, serializer/generator drift) flips
that chunk to normal storage — the flip is the safety mechanism, erosion is
bounded to chunks the server actually loads. Whole-mode stores (entities,
POI) remain exempt: entity NBT is not worldgen-reproducible.

With this, every exemption that kept huge worlds heavy is gone. The
"make worlds weigh less" roadmap is fully measured-closed: codecs (§5-§7),
per-section CM (§6), global CM (§7.2), export framing (§7.3), and now the
import half of the semantic lever (§2/§8/§9). Remaining bytes on a pure
worldgen world: contracts (26 B/chunk) + entities/POI (real data, exempt by
construction) + whatever the server actually edits (stored honestly).

## 10. Research tick 6 — strip-canonical contract legends (v0.9.46): erosion measured and closed

§9's raw-only contract flips on the first byte-different re-save. A real
Paper session relights and re-saves contracted chunks (fresh section light,
bumped InhabitedTime/lastUpdate, HashMap-key-order drift) the moment a
player merely walks past — flying over a pregen world erodes every chunk
the client renders. Measured head-on (pristine_canon_probe, production
import + write paths, real 728-chunk corpus):

| run (same session) | after one relight session | compact vs anvil 4.47 MiB |
|---|---|---|
| canon OFF (0.9.45 raw-only legend) | pristine=0, stored=728 — EVERY contract flipped | 1.45 MiB, x0.32 (-68%) |
| canon ON (v0.9.46 strip-canonical legend) | **pristine=728, stored=0** | **0.02 MiB, x0.0054 (-99.5%)** |

The legend: `chunknbt::canonical_contract_hash` = order-free structural
digest (`structural_hash`, sorted-key compounds) after removing
`lastUpdate`/`LastUpdate`/`InhabitedTime` from the root and
`strip_derived_chunk`'s set (SkyLight/BlockLight/starlight state bags,
isLightOn canonicalized to 0) from the sections. Everything else —
DataVersion, Status, palettes/blocks/biomes, Heightmaps, block_entities —
stays hashed, so real seeded-content changes still flip. Wire:
`[mode 7][raw 16B][canon 16B]` = 33 B; 17 B raw-only contracts (0.9.44/45
containers) parse with canon=None and behave exactly as before; the O(1)
raw fast path is untouched. `CSAVES_PRISTINE_CANON=0` restores raw-only
formation.

Honest costs: canonical formation ~2.3 ms/chunk on the corpus (728 chunks,
23 MB payload: full parse + order-free digest, 2-core sandbox) — rides the
background import drain, opt-out documented. keys_probe side measurement:
the import REBUILD form differs from the raw payload under the canonical
hash for 204/728 corpus chunks — CSEC canonical palette order vs vanilla
order in rebuilt sections. Irrelevant for contracts: Paper REGENERATES a
contracted chunk (read = None BY DESIGN), so the re-save comes from Paper's
own serializer, not from our rebuild; the probe pins this reasoning and
replays the session against relit(raw).

With §10 the semantic line is again measured-closed: erosion was the last
way the huge-world win could silently decay in production. Remaining bytes
on a pure worldgen world: contracts (42 B/chunk with the legend) +
entities/POI (exempt by construction) + what the server actually edits.
Next honest frontiers are tooling (contract/regen-drift audits) and the
shim-side isNewChunk/InhabitedTime tightening — no byte-level lever left.

## 11. Research tick 7 — shim-evidence pristine gating (v0.9.47): the residual risk closes at the source

§8's contract shipped with one documented, operator-accepted residual risk:
mutations between worldgen and a chunk's FIRST durable save were hashed INTO
the contract and silently reverted on regeneration (read=None BY DESIGN).
§10 named the frontier: "the shim-side isNewChunk/InhabitedTime tightening".
v0.9.47 ships it — and the design turned out simpler than the §2 sketch
feared: NO Paper patch, NO generation-write instrumentation. The evidence
already rides in the chunk tag the server hands the shim on every write.

**Evidence rule** (`SavesShim.isFreshChunk`, applied on BOTH write paths —
Moonrise `moonrise$startWrite` and the legacy sync `write`):

- `Status == "minecraft:full"` — proto-stage saves never contract. This
  also kills a latent erosion class: a proto contract could only flip on
  the later full re-save (proto→full changes blocks/palettes, the canon
  legend cannot absorb it); now proto content stores honestly instead of
  forming a doomed contract.

## 23. Research tick 19 — the container is the world (v0.9.59): Anvil becomes a view, never a file

Every preceding tick measured the round-trip: vanilla saves Anvil, the
module compresses it into the container, `export_dir` materializes Anvil
back when the world is needed. Whatever the ratios, that framing keeps
one asterisk alive — somewhere on disk, a .mca file exists. This tick
removes the asterisk at the storage layer: the .mca form must not exist
on disk AT ALL, not while playing, not between sessions. Anvil stops
being a stored artifact and becomes a RENDERING the engine asks for.

**Three pieces.** First, `build_region_body` — the per-region writer
extracted from `export_dir` (the v0.9.58 streaming core: one chunk
payload resident at a time, the v0.9.49 two-meanings-of-None rule
preserved per chunk). One region builder now feeds TWO consumers; there
is one code path and one truth. Second, `serve_region(store, rx, rz)` —
renders any region's exact vanilla bytes IN MEMORY from the container:
location table, zero timestamps, zlib body — byte-for-byte what
`export_dir` would write, nothing touches the disk. Third,
`serve_chunk(store, cx, cz)` — the engine-hook entry a mod shim would
call on a chunk read: the single region entry (len + type + zlib
payload), decompressing bit-exactly to the stored payload. `None` is
absent-by-contract: a pristine contract regenerates from the seed, an
unknown chunk does not exist — vanilla semantics, unambiguous.

**The takeover punchline.** `import_dir` already DRAINS the .mca files
it reads (the unlink was always there — now it means something): a world
imported from vanilla ceases to exist in Anvil form the moment it lands
in the container.

**The CI gate (`serve-bench`, job 3 of 9).** 65,536 chunks, 64 regions:
take over a vanilla-saved world (pristine import), live-edit EVERY chunk
in place (the 0.9.57 constructive edit, parallel), then assert the disk
truth — a recursive walk of the whole world tree counts ZERO .mca files.
`serve_region` re-renders all 64 regions byte-identical to the derived
export view (64/64). The SERVED bytes — nothing else — are written to a
scratch directory and re-imported into a fresh store: every chunk
verified semantically against the edited content (canonical section
equality), ok=65,536 bad=0. `serve_chunk` matches the region-slot bytes
on a 1,024-entry sample. A world that exists only as our container
yields, on demand, a fully valid vanilla world.

**Local numbers (side=3, 9,216 chunks, 100% live content).** Container
2,755,527 B = x0.0729 of the Anvil view (37,822,464 B); per-region serve
~0.8 ms mean (first 773 ms, p90 900 ms — in-memory, no disk); replay
9,216/9,216 ok, bad=0. 77/77 tests green (two new: serve-vs-export byte
identity, serve_chunk framing + pristine-None).

**What remains.** The Java-side shim: a mod (Fabric mixin on the engine's
RegionFile IO, or a Paper plugin) that points chunk reads/writes at

format, lifecycle, verification, and the zero-.mca guarantee — is done

## 24. Research tick 20 — the server plays from the container (v0.9.60): the live path, gated end to end

v0.9.59 made Anvil a rendering; this tick gates the live SESSION. The

(cplugin_init), retransforms RegionFileStorage and binds its natives
(nReadChunk / nWriteChunk(fresh) / nEndSave) to a store registry. The
new `play_probe` drives exactly that surface — `Registry::attach` (the
natives' own registry), `write_chunk_fresh` (the freshness-evidence
channel where Paper's chunk tag is in hand), `read_chunk` (None =
ReadResult::NO_DATA → the engine regenerates from the seed), `sync`
(the nEndSave barrier) — through a complete session with a restart in
the middle. To make that surface honest API, `engine` and `natives`
became public modules.

**The session (16,384 chunks, CI job `play-bench`).** Worldgen burst:
every chunk saved with the freshness evidence (Status=minecraft:full,
InhabitedTime==0) → 16,384 regeneration contracts, ZERO stored blobs —
on the live path worldgen is never stored, the elision is not an
optimization of some saves but the DEFAULT of all first saves. Play:
169 sampled contract loads verified `read = None` + canon legend ==
`canonical_contract_hash` of a FRESHLY serialized worldgen form — the
load-bearing subtlety: NBT byte order is not stable across
serializations (compound maps iterate in hash order), so the raw hash
is serialization-dependent while the canonical structural hash is
stable; this is exactly why the write path matches byte-different
relight re-saves against the canon legend (v0.9.46) and why the probe
asserts canon, not raw. Edits: 4,096 dirty saves with fresh=false flip
to honest storage (the v0.9.47 mutation-safety rule — a contract can
never swallow a live edit); 4,096 unchanged re-saves of worldgen
chunks stay contracted through the identical/canon fast paths. Restart:
sync, every handle dropped, a FRESH registry reopens the same dir — the
new server process. Reload: 4,096/4,096 edits verify semantically,
12,288/12,288 contract legends regenerate to their worldgen form,
0 lost. Disk truth: 0 .mca files anywhere under the world tree.

**Weight.** The session container weighs 358 B/chunk across all keys —
4,096 stored chunks (~250 B each, the player-built content) + 12,288
contracts (~35 B each). The played world's storage cost converges to
the stored fraction: every chunk the player never touched costs 35 B
forever, every chunk they touched costs what worst_case_probe already
proved (~250 B on 100% content).

## 25. Research tick 21 — the JVM gate (v0.9.61): a real JVM drives the production natives

**The unproven half.** v0.9.60 gated the live path from the Rust side:
play_probe calls `Registry::attach` / `write_chunk_fresh` / `read_chunk`
in-process. But the actual integration is JAVA calling Rust over JNI —
`byte[]` → `GetPrimitiveArrayCritical` → zstd tiers and back through
`NewByteArray`/`SetByteArrayRegion`, `null` meaning NO_DATA — and none
of that marshalling had ever run under a gate. The CRUSSTY kernel was
also the only way to bind: `cplugin_init` needs the kernel ABI, so a
plain `java` process could not reach the natives at all.

**The bridge.** `native/src/jvmgate.rs` adds standard-JNI exports
(`Java_dev_crussty_saves_jvmgate_JvmGate_nActive/nAttach/nReadChunk/
nWriteChunk/nBeginSave/nEndSave/nMarkAutosave`). Each is a one-line
pass-through into the corresponding `natives::n_*` function — the same
registry the shim binds via RegisterNatives, zero duplicated logic.
The JVM resolves the symbols itself; no kernel, no JVM TI, no shim
needed. The product binding path is untouched.

**The harness** (`java/dev/crussty/saves/jvmgate/JvmGate.java`) builds
chunk NBT on the Java side — a minimal NBT writer emits sections
`{Y, block_states{palette: strings, data: longs}, biomes{palette}}`
with 4-bit LSB-first packed indices (16 per long, the vanilla
`pack_nostroddle` layout), deterministic xorshift content, ~18 KiB per
chunk — and verifies reloads with a minimal NBT parser: it re-walks the
read-back chunk and asserts every block of every section sits on its
exact position, plus the root tags (Status, xPos).

**Byte equality is deliberately NOT the gate.** The store re-encodes
sections canonically on the write path; the experiment on the microtest
corpus shows the canonical form REVERSES the incoming palette order
(input `[a,b,c]` → stored `[c,b,a]` with data rebuilt to match —
semantically neutral, exactly the "palette order permutes" note the
semantic-equality helpers have carried since v0.9.44). A byte gate
would either fail on every chunk or force the harness to mirror the
canonicalizer; block-position equality asserts the property the player
actually cares about and stays correct under any future canonical
form. The harness still counts what it can: the NBT parse itself
rejects structural damage, the grid walk rejects positional damage.

**The session, CI-gated (jvm-bench, two JVM processes, 16,384 chunks,
8 threads):**

- write: 16,384 competitive parallel JNI writes in 6.65 s
  (mean 406 µs/write) — pure `byte[]` marshalling into the real tiers;
- the `nBeginSave`/`nEndSave` barrier (fsync) passes, `nMarkAutosave`
  is a no-op, then `System.exit` — server death;
- verify: a FRESH JVM process reopens the SAME container dir —
  semantic verify 16,384/16,384 (NBT parse + block-position equality,
  17.4 s including the parse);
- read burst: 32,768 concurrent JNI reads over the reopened container —
  p50 ≈ 127 µs, mean chunk ~18 KiB;
- the whole gate runs in ~30 s of CI time.

**What the gate caught while being built** (the reason it exists):
(1) the first harness payload was not valid NBT and every write
correctly returned false — the natives' error channel works end to
end; (2) `read_chunk` after reopen returns canonical re-encodings, not
the written bytes — the byte-equality assumption died in the first
local run, and the semantic gate is what remains honest; (3) a Java
side without the kernel now has a first-class, CI-gated path to the
engine, which is exactly the surface any future mod-side integration
(Fabric/Paper plugin) will reuse.

**77/77 tests green.** The CI matrix is now 11 jobs.
